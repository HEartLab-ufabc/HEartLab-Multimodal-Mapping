# 3D Reconstruction Processing

This directory contains the processing software used to generate an experiment-specific 3D surface model from the rotational image sequence acquired with the HEartLab 3D reconstruction system.

The reconstruction workflow is based on **silhouette extraction followed by rotational space carving (visual-hull reconstruction)**. A triangular surface mesh is subsequently generated from the carved voxel volume.

The image-acquisition software is maintained separately because HEartLab has used different camera interfaces:

- [`../3D_reconstruction_capture_labview/`](../3D_reconstruction_capture_labview/) — LabVIEW acquisition for the EVT camera system;
- [`../3D_reconstruction_capture_python/`](../3D_reconstruction_capture_python/) — Python/OpenCV acquisition for the Imaging Source USB camera.

## Workflow

The reconstruction consists of:

```text
Camera calibration
      ↓
Rotational image acquisition
      ↓
Image undistortion
      ↓
Silhouette extraction / manual correction
      ↓
Optional silhouette-axis alignment
      ↓
Rotational space carving
      ↓
Voxel visual hull
      ↓
Triangular surface generation
      ↓
Optional mesh smoothing / export
```

For the standard rotational acquisition used in the manuscript, approximately **100 views are acquired over 360°**, corresponding to **3.6° between consecutive images**.

## Camera calibration — MC-Calib

Camera calibration is performed separately using **MC-Calib**:

https://github.com/rameau-fr/MC-Calib

This repository does **not** reproduce the MC-Calib installation or calibration instructions. Follow the upstream MC-Calib documentation directly.

The reconstruction program expects the MC-Calib camera-parameter output file, normally:

```text
calibrated_cameras_data.yml
```

The current processing code reads the selected camera's:

- `camera_matrix`;
- `distortion_vector`;
- `distortion_type`;
- `camera_pose_matrix`.

The intrinsic and distortion parameters are used to undistort the rotational images before silhouette extraction. The camera-pose matrix is retained for traceability but is **not currently used to perform a projective multi-camera carving calculation**.

The ChArUco calibration geometry and dimensions used for the experiments should be reported in the associated manuscript and experimental documentation. The authoritative procedure for generating and processing the calibration dataset remains the MC-Calib documentation.

## Main program

### `SpaceCarvingReconstruction.py`

This is the recommended reconstruction-processing program for the repository and is the code path that most closely matches the method described in the manuscript.

It provides:

- loading of MC-Calib camera parameters;
- perspective or fisheye image undistortion according to the MC-Calib distortion model;
- natural/numeric ordering of rotational images;
- threshold-based silhouette extraction;
- largest-component selection;
- manual add/erase correction;
- polygon-based silhouette correction;
- configurable angular increment;
- rotational voxel carving;
- saving/loading of silhouette masks;
- saving/loading of the carved voxel volume;
- surface generation using marching cubes;
- optional mesh smoothing;
- PLY/STL/OBJ export.

### Standard angular sequence

For 100 images:

```text
image 0  →   0.0°
image 1  →   3.6°
image 2  →   7.2°
...
image 99 → 356.4°
```

The saved silhouette filenames record the **absolute angular position**:

```text
st_000_0.0.png
st_001_3.6.png
st_002_7.2.png
...
st_099_356.4.png
```

This avoids ambiguity between angular increment and absolute view angle.

## Optional silhouette alignment

### `AlignSilhouettes_PCA.py`

This utility performs an optional **in-plane silhouette alignment** by calculating the dominant principal axis of the union of all silhouette masks, rotating it toward the vertical image axis, and translating the common centroid toward the horizontal image center.

This utility should **not** be described as camera calibration or as a direct estimate of camera pose. It uses the shape of the segmented preparation itself and is therefore only an alignment aid.

Use it only when this correction is appropriate for the experimental dataset and document its use with the reconstruction output.

If the physical rotation axis is available as a known reference in the images, alignment to that known axis is preferable to assuming that the preparation's principal anatomical axis represents the mechanical rotation axis.

## Metric scale

The reconstructed voxel volume and the mesh generated by `SpaceCarvingReconstruction.py` are expressed in **voxel coordinates** unless a separately validated metric scale is applied.

Camera focal length alone does not provide a valid direct conversion from voxel index to millimetres. The previous development script attempted to derive millimetres using factors proportional to `1/fx` and `1/fy`; this should not be interpreted as physical metric calibration.

If absolute dimensions are required, a validated mapping between reconstruction-space voxels and the physical calibration geometry must be established and documented separately.

Do not label mesh coordinates as millimetres unless that spatial calibration has been verified.

## Output

A typical reconstruction directory can contain:

```text
reconstruction_output/
├── silhouettes/
│   ├── st_000_0.0.png
│   ├── st_001_3.6.png
│   └── ...
├── voxel_matrix/
│   └── visual_hull_voxels.npy
└── mesh/
    └── reconstructed_surface.ply
```

The exact output filename is selected by the user when the mesh is exported.

## Requirements

Install Python dependencies with:

```bash
python -m pip install -r requirements.txt
```

`tkinter` is normally included with standard Python installations on Windows. On some Linux distributions it may need to be installed separately.

For the publication release, the versions used on the reconstruction workstation should be recorded and pinned in `requirements.txt` or in the release documentation.

## Running

```bash
python SpaceCarvingReconstruction.py
```

Recommended order:

1. load the MC-Calib `calibrated_cameras_data.yml` file;
2. select the camera corresponding to the reconstruction image sequence;
3. load the rotational image folder;
4. select an output directory;
5. verify the angular increment (3.6° for the standard 100-view acquisition);
6. review and correct each silhouette as required;
7. carve each accepted silhouette;
8. save the voxel matrix as an intermediate result;
9. generate the mesh;
10. optionally smooth and export the mesh.

## Important assumptions and limitations

The current implementation is a rotational visual-hull reconstruction and assumes that:

- the camera remains fixed during the rotational sequence;
- the preparation rotates around a stable mechanical axis;
- the angular increment is known;
- the image sequence is ordered correctly;
- silhouettes represent the external boundary of the preparation sufficiently well;
- the rotation axis and image geometry are adequately aligned for the orthographic-style carving approximation used here.

The method reconstructs the **externally visible visual hull**. Concavities that are not represented in any silhouette cannot be recovered by silhouette-based space carving.

## Files not recommended as the canonical manuscript workflow

Several earlier development scripts were used while the reconstruction workflow was being developed. They should not be presented as the canonical implementation associated with the manuscript unless they were specifically used to produce a reported result.

### `3DReconstruction.py`

Early proof-of-concept implementation. It omits the first image from its loaded image list and directly applies full-resolution silhouettes to a small voxel block, making it unsuitable as the current reference implementation.

### `3DReconstruction_open3d.py`

Development version using Open3D visualization. It contains rotation logic based on integer multiples of 90° in one code path, which is incompatible with the 3.6° acquisition used in the manuscript, and contains obsolete variable/function references.

### `GenerateMeshHull.py`

Alternative point-cloud/mesh experiment using rotated silhouette perimeters and Delaunay-based surface generation. It is **not rotational space carving** and therefore does not represent the reconstruction method described in the manuscript.

### `GenerateMeshBPA.py`

Alternative point-cloud/mesh experiment using rotated silhouette perimeters and Ball-Pivoting surface reconstruction. It is also **not rotational space carving** and should be treated as an experimental alternative rather than the manuscript reconstruction pipeline.

### `CorrectCameraTilt.py`

Manual development utility for silhouette rotation. If retained, it should be labeled as a legacy/manual alignment tool rather than a camera-calibration procedure.

### `CorrectCameraTilt_PCA.py`

Earlier automatic alignment utility. The replacement `AlignSilhouettes_PCA.py` uses clearer principal-axis logic, removes hard-coded paths, and explicitly identifies the operation as silhouette alignment rather than camera calibration.

## Reproducibility

For a reconstruction associated with a publication or dataset, preserve:

- repository release or Git commit;
- acquisition application and version;
- camera model;
- MC-Calib calibration output;
- image count and angular increment;
- original rotational images;
- accepted/corrected silhouettes;
- voxel-matrix output;
- mesh output;
- any alignment or smoothing step applied.
