# 3D Reconstruction Image Acquisition — LabVIEW / EVT Cameras

This directory contains the LabVIEW software used by HEartLab to automate rotational image acquisition for experiment-specific three-dimensional reconstruction of cardiac preparations.

The software coordinates image capture from the **EVT camera system used in the HEartLab implementation** with controlled rotation of the preparation.

> [!IMPORTANT]
> This LabVIEW application is configured for the EVT camera system used in HEartLab. Because the camera interface and acquisition workflow are manufacturer- and configuration-specific, the application should **not be expected to work directly with generic USB cameras or cameras from other manufacturers** without modification.

A separate Python/OpenCV implementation used with the Imaging Source USB-camera setup is available at [`../3D_reconstruction_capture_python/`](../3D_reconstruction_capture_python/).

## Purpose

The application performs the **image-acquisition stage** of the reconstruction workflow. An acquisition consists of approximately 100 images acquired over one complete 360° rotation of the preparation.

The resulting multi-view image sequence is subsequently used for segmentation and 3D surface reconstruction. This LabVIEW application does **not** itself perform the complete surface-reconstruction process.

## Acquisition principle

```text
Initial orientation
        |
        v
Capture image
        |
        v
Rotate preparation
        |
        v
Wait for mechanical stabilization
        |
        v
Capture next image
        |
        v
Repeat until 360° is covered
```

For a 100-view acquisition:

```text
360° / 100 = 3.6° per image
```

## Hardware interface

The software communicates with the rotational-stage Arduino controller through a serial connection.

The corresponding firmware is available at:

[`../../firmware/stepper_motor_control/`](../../firmware/stepper_motor_control/)

The general architecture is:

```text
EVT camera
    |
    v
LabVIEW acquisition software
    |
    +-- image capture
    |
    +-- serial rotation command
              |
              v
           Arduino
              |
          STEP / DIR
              v
       Stepper driver
              |
              v
       Stepper motor
              |
              v
      Rotating preparation
```

## Representative acquisition parameters

| Parameter | Value |
|---|---:|
| Total rotation | 360° |
| Number of views | 100 |
| Angular increment | 3.6° |

These values correspond to an implementation and may be adapted when a different angular sampling density is required.

## Camera compatibility

The current LabVIEW application was developed around EVT cameras and their associated acquisition interface.

Compatibility with the following should **not** be assumed:

- generic USB webcams;
- USB machine-vision cameras using unrelated drivers;
- cameras from different manufacturers;
- different EVT camera models using incompatible drivers or APIs;
- operating-system or driver versions not tested with the original setup.

Porting the application to another camera may require changes to camera discovery, driver calls, acquisition configuration, exposure control, frame capture, image saving, trigger behavior, and error handling.

## Tested environment

The HEartLab implementation was used with:

- LabVIEW 2019;
- 64-bit architecture;
- Windows 10/11;
- EVT HR-1800-S-M camera.


## Operation

A typical acquisition sequence is:

1. position the preparation at the initial orientation;
2. verify the EVT camera connection;
3. verify camera focus, exposure, and field of view;
4. verify any calibration object required by the reconstruction workflow;
5. connect the Arduino rotational controller;
6. select or verify the serial port;
7. select the output directory;
8. verify the angular increment and intended number of views;
9. begin automated acquisition;
10. allow the application to alternate image capture and rotation;
11. verify that all expected images were saved;
12. preserve the acquisition parameters with the dataset.

## Output

The output generated by the current LabVIEW application:

- 101 images (the first and last images should be the same for validation);
- ".tiff" format;
- 1600x1000 pixels;
- 8-bit depth;

## Calibration and reconstruction

The image-acquisition stage is followed by camera calibration and the silhouette/space-carving workflow provided in [`../3d_reconstruction_processing/`](../3d_reconstruction_processing/). Camera calibration follows the upstream MC-Calib procedure.

## Verification

Before acquiring reconstruction images:

- verify serial communication;
- verify the mechanical transmission ratio;
- confirm that the preparation can rotate without tubing or cable interference;
- verify EVT camera focus and exposure;
- verify that images are written to the intended directory;
- confirm that the final acquisition contains the expected number of views.

> [!CAUTION]
> The software and acquisition parameters are provided as a representative HEartLab implementation. Camera communication, angular calibration, file output, and mechanical rotation must be independently verified before experimental use.
